Why it exists

Diagram-as-code usually still asks the author to think like a diagram designer. Visual Workbench moves authoring up a level so the same semantic source can answer different business questions without being redrawn.

01

Model meaning, not pixels

Steps, systems, data, roles, decisions, checkpoints, risks, outcomes, lanes, and relationship types are first-class semantic objects.

02

Generate views for the reader

Named views can focus on executive flow, data, controls, exceptions, or a custom question while preserving meaningful connectivity.

03

Keep a visual grammar

Method policies, semantic status, automatic lanes, edge routing, and deterministic rendering keep outputs coherent across many diagrams.

Visual methods are policies

process, checkpoint-flow, data-flow, system-flow, plan, roadmap, timeline, handoff, dependency-map, and relationship select different layout behavior rather than acting as decorative labels.

Not a drawing canvas. If the requirement is “move this box 12 pixels,” the source model is at the wrong abstraction level. Change the meaning, method, view, or renderer policy instead.

Generated proof, not mockups

Every image below is rendered during the GitHub Pages build from committed example models using the same CLI and renderer shipped by the repository. A renderer change therefore changes the public proof surface too.

Machine-readable build inventory: gallery/manifest.json. Source examples and exact render commands remain public in the repository and Pages workflow.

Where it connects

Visual Workbench is the presentation layer the rest of the toolkit can grow into: structured contracts and graphs already contain the semantics needed for useful business views.

Agent entry point

Teach agents to model before rendering.

The repository's agent rule is deliberately simple: do not draw; model meaning. Schema validation and reusable skills help an agent choose a visual method, define compact semantics, and render deterministically.

DISCOVER

Manifest + skills

agent-manifest.json, schema.json, AGENTS.md, and reusable skills/ define the authoring contract.

MODEL

Choose the reader's question

Pick the method and view from what must be understood, not from a desired collection of shapes.

RENDER

Keep output deterministic

Agents may create or transform metadata; layout and final presentation remain renderer responsibilities.

Stop redrawing the same system for every audience.

Model the meaning once, then let each view remove the detail its reader does not need.
