# Visualize plan

Default to `plan`. Model outcomes and milestones before tasks. Add `checkpoint` nodes for gates and `risk` nodes only for risks that can change the plan.

Use `roadmap` when stages/capability progression are the core message. Use `timeline` only when chronological order or dates are the core message.

Avoid turning a plan into a dense project-management Gantt. The first visual should explain direction and decision points.
